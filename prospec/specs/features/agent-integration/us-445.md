### US-445: Skill boundaries and localized exclusions [P1]

As an AI agent discovering Prospec alongside other skills,
I want explicit skill boundaries and localized exclusion phrases,
so that I can choose the intended SDD station and understand the metadata loaded each session.

**Acceptance Scenarios:**
- WHEN inspecting the skill registry, THEN every description names its negative scope and triggers exclude the bare words review, tasks, and design
- WHEN localized exclusions are configured, THEN the entry config and skill frontmatter share the same Not for clause
- WHEN localization runs, THEN the scaffold and validated write cover both trigger and exclusion gaps
- WHEN reading either root README, THEN finisher metadata costs are described consistently

#### REQ-TYPES-097: Skill exclusion baseline and `skill_exclusions` config key
`SkillConfig` gains an optional `exclude: string[]` — the English baseline of the skill's negative scope as short phrases (e.g. `ad-hoc PR review`), the translation source for localized exclusions and nothing else. `ProspecConfigSchema` gains `skill_exclusions: z.record(z.string(), z.array(z.string())).optional()`, a sibling key of the same shape as `skill_triggers`, which is unchanged.
- WHEN reading `SKILL_DEFINITIONS`, THEN every skill carries a non-empty `exclude` whose phrases restate the boundary clause already in its `description`
- WHEN `.prospec.yaml` has no `skill_exclusions`, THEN it validates exactly as before
- WHEN `skill_exclusions` names a skill, THEN its value is a string array; an empty array reads as unset

---


#### REQ-SERVICES-110: Exclusion scaffold, write-back and `Not for:` rendering
`trigger-localization` exposes `computeUnlocalized(config, kind: 'triggers' | 'exclusions')` as the single fill-missing source; `computeUnlocalizedSkills` remains as its `triggers` wrapper. `agent-triggers` prints a `skill_exclusions:` block after `skill_triggers:` (baselines from `SkillConfig.exclude`) and `--write` inserts the missing keys of both maps in one validated write. `agent-sync` renders each skill's description through one exported `renderSkillDescription(skill, localizedExclusions)` used by both the entry-config registry and the SKILL.md frontmatter (inner whitespace in a phrase is collapsed, so a phrase cannot mint a new line in the entry config): the plain `description` when no localized exclusions exist, otherwise `<description> Not for: <phrases joined by '; '>.` — the English baseline is never rendered because the English boundary already lives in the description.
- WHEN `skill_exclusions` is absent or a skill's entry is an empty array, THEN every generated file is byte-identical to the output without the key
- WHEN a skill has localized exclusions, THEN both the entry-config line and the SKILL.md frontmatter carry the same `Not for:` clause, passed through the existing `escapeYamlScalar` exit
- WHEN `prospec agent triggers` runs on a non-English project, THEN the scaffold lists the skills lacking a `skill_exclusions` entry with their English `exclude` baseline, below the `skill_triggers:` block
- WHEN `--write` runs, THEN only missing keys of `skill_triggers` and `skill_exclusions` are inserted, in one `ProspecConfigSchema` re-validation and one atomic write; a failing document leaves `.prospec.yaml` unchanged
- WHEN the agent-sync population hint renders, THEN its gap set is still the `skill_triggers` gap (REQ-AGNT-021) while its wording names both maps and the `--write` command, because the scaffold it points at prints both blocks

#### REQ-TEMPLATES-231: Finisher skills name both localization keys
The trigger-localization step of `prospec-quickstart` and `prospec-upgrade` states that the `prospec agent triggers` scaffold lists both `skill_triggers:` and `skill_exclusions:` blocks and that both are translated in place and written back with `--write`.
- WHEN either skill is rendered, THEN its localization step names `skill_exclusions` alongside `skill_triggers`
- WHEN the sentence is removed from a template, THEN the section-scoped contract assertion turns red

#### REQ-AGNT-043: README states the finisher skills' per-session cost honestly
Both root READMEs describe `prospec-quickstart` and `prospec-upgrade` as excluded from the always-loaded entry config while each deployed `SKILL.md`'s name and description still load per session.
- WHEN `README.md` is read, THEN the finisher note does not contain `zero ongoing token cost`
- WHEN `README.zh-TW.md` is read, THEN the finisher note does not contain 「不增加任何重複性 token 成本」 and states the same fact as the English note

#### REQ-TESTS-117: Negative-scope, trigger-hygiene and exclusion no-op contracts
`tests/contract/skill-format.test.ts` asserts, for every `SKILL_DEFINITIONS` entry: the description contains a boundary clause (matched by `/[—–\-;,]\s*not\s/i`), contains none of the harness/plugin names in a banned-word list, its triggers include none of the bare words `review`, `tasks`, `design`, and its `exclude` is a non-empty string array. A further assertion (in the agent-sync service unit suite, where the render context is observable) renders agent sync twice — once without `skill_exclusions`, once with an empty-array entry — and asserts zero diff.
- WHEN a description loses its boundary clause or gains a harness name, THEN the assertion names the skill
- WHEN a bare word returns to a trigger baseline, THEN the assertion names the skill and the word
- WHEN the empty-array and absent-key renders differ, THEN the no-op contract turns red
