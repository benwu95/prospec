## US-448: Consistent behavioral claims across authored and generated surfaces [P1]

As a maintainer writing Prospec requirements and documentation,
I want component-scoped authoring rules,
So that behavioral claims match the code they describe.

**Acceptance Scenarios:**
- WHEN a Spec block or documentation claim is authored, THEN its guidance constrains component scope, predicate wording, quantifiers and causal clauses.

#### REQ-TEMPLATES-241: Claim-authoring rules
Claim-authoring guidance states a component’s own guarantees, derives set and condition wording from implementation predicates, deletes a wrong claim by default, writes rules as general positive statements (a general negative only where one line replaces several positive ones), and uses quantifiers or causal clauses only when they hold throughout the stated scope. Authors otherwise remove the claim or reference the owning requirement.
- WHEN work in this repository loads its core conventions, THEN the authoring guidance is available in their skill and documentation authoring section.
- WHEN the shipped delta-spec format’s Spec section or Docs-Claims lens is read, THEN the authoring rules are available without a new mandatory Startup Loading item.
- WHEN shipped guidance renders, THEN the guidance describes Prospec behavior without repository-specific scripts, tests, playbook ids or harness/model/vendor names.
- WHEN the guidance addresses tests, THEN it directs them at behavior and structure rather than a negative string assertion per retired phrasing.
