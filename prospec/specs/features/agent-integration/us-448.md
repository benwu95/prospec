## US-448: Consistent behavioral claims across authored and generated surfaces [P1]

As a maintainer writing Prospec requirements and documentation,
I want component-scoped authoring rules and shared canonical phrases,
So that repeated behavioral claims retain the same meaning across runtime messages, skills and bilingual documentation.

**Acceptance Scenarios:**
- WHEN a registered rule is rendered or documented, THEN each declared consumption site uses its canonical phrase.
- WHEN a Spec block or documentation claim is authored, THEN its guidance constrains component scope, predicate wording, quantifiers and causal clauses.
- WHEN a phrase disappears, is paraphrased or leaves its declared scope, THEN the corresponding contract fails.

#### REQ-TYPES-109: Bilingual canonical phrase and consumption-site registry
The types layer defines canonical English and Traditional Chinese phrases and their registered consumption sites. A site identifies its language, source kind and bounded location; general Knowledge synchronization and its backfill variant have separate phrases.
- WHEN a rule is restated at three or more surfaces, THEN authoring guidance requires registering its canonical phrase and consumption sites.
- WHEN consumers need a registered phrase, THEN runtime consumers import the definition and templates receive the definition through their render context; the related-module condition covers both knowledgeSyncReasons messages and routeChange blocking gates without changing next or route codes.
- WHEN the initial registry is read, THEN it covers the related-only unregistered-module condition and the Knowledge synchronization sets, including the backfill variant.
- WHEN archive names the backfill synchronization set at Entry Gate or Phase 4, THEN both sites consume the registered backfill phrase

#### REQ-SERVICES-125: Canonical phrase injection through existing generation paths
Agent sync injects canonical claim text from the types registry into skills and references. The shared init-document context supplies the same definitions to lifecycle templates rendered by init and upgrade.
- WHEN agent sync renders a registered phrase site, THEN its output contains the registry text and the template contains a value reference rather than a handwritten copy.
- WHEN init or upgrade renders the lifecycle document, THEN the registered phrase is present through the shared init-document context.
- WHEN the phrase source changes, THEN regenerated outputs use the changed definition without changing knowledge-sync classification, gate predicates or route codes.

#### REQ-TEMPLATES-241: Claim-authoring rules
Claim-authoring guidance states a component’s own guarantees, derives set and condition wording from implementation predicates and quotes registered canonical phrases verbatim, and uses quantifiers or causal clauses only when they hold throughout the stated scope. Authors otherwise remove the claim or reference the owning requirement.
- WHEN plan or implement loads this repository’s PB-003 through its existing station Playbook read, THEN the authoring guidance is available and the entry declares plan, implement and review among its stations.
- WHEN the shipped delta-spec format’s Spec section or Docs-Claims lens is read, THEN all three authoring rules are available without a new mandatory Startup Loading item.
- WHEN shipped guidance renders, THEN canonical wording describes Prospec behavior without repository-specific scripts, tests, playbook ids or harness/model/vendor names.

#### REQ-TESTS-129: Per-site phrase contracts and mutation evidence
Repository contracts compare registered canonical phrases with bounded authored, runtime and generated sites, and pin authoring rules within their designated sections. The site inventory is checked independently of the registry’s iteration so removing a descriptor does not produce a vacuous pass.
- WHEN a registered site deletes, paraphrases or moves its required phrase outside the declared scope, THEN that site’s contract fails and an applied mutation demonstrates the failure.
- WHEN a shipped template is mutated, THEN its bundle is rebuilt before evaluating the rendered contract, and the source and bundle are restored afterwards.
- WHEN Feature Spec wording is pending graduation, THEN a separate station audit checks the resulting Spec blocks; the archive change registers and tests the graduated sites. The standing suite reads version-controlled sites without depending on an active-change directory or skipping a missing site.
- WHEN exact weight baselines change, THEN they are regenerated as UTF-8 while cumulative mandatory-context and reference ceiling anchors remain unchanged or shrink.
- WHEN the change is validated, THEN contract, unit, integration, e2e, lint, typecheck, coverage, factual-count, generated-agent, Knowledge-sync and strict drift checks pass.
- WHEN a shipped-claim audit is completed, THEN its change artifact inventories every skill, partial, reference and change template with dispositions and evidence, including intentionally retained claims
- WHEN the shipped-claim audit changes exact baselines, THEN the cumulative mandatory context and total reference tokens do not increase from their pre-change totals; ceiling anchors are not raised
