### US-446: One registry behind every station reference map [P1]

As a developer maintaining the Prospec skills,
I want each reference's phase, purpose, loading condition and deployment to come from a single definition,
so that a re-synced host carries the same guidance everywhere and no load point is lost to a second, hand-maintained copy.

**Acceptance Scenarios:**
- WHEN agent sync runs, THEN each station's reference list and loading timing stay equivalent to the version-controlled baseline, and the reference set is unchanged
- WHEN the four supported hosts are synced, THEN every host receives the same reference set, and a shared output directory is written once
- WHEN the workflow-eval mandatory policies are rebuilt, THEN each scenario's policy values and ceilings are unchanged and traceable to the same registry

#### REQ-TYPES-099: Canonical Station Reference Registry
The types layer owns STATION_REFERENCES, the canonical mapping from every shipped skill to ordered phase/reference entries, deployment metadata, purpose and applicability. Empty skills have explicit empty entries; deployment inventories, rendered phase maps and status projections derive from it rather than independently maintained maps.
- WHEN a reference is used in multiple phases, THEN each phase association is retained and only the deployment projection deduplicates the file.
- WHEN loading timing is declared, THEN startup mandatory, in-phase and conditional references remain distinct; scale and UI-scope predicates are typed data, and other runtime conditions remain visible guidance.
- WHEN a skill has no references or is not a linear SDD station, THEN the registry still represents it without adding a lifecycle station or inventing files.

#### REQ-TEMPLATES-232: Registry-Generated Prose with Preserved Reference Maps
Agent sync renders the skill reference maps from STATION_REFERENCES and derives each skill's deployed references from the same entries. Instructions, phase associations, mandatory/on-demand timing and reference sets stay equivalent to the version-controlled baseline captured before the registry existed, and the prose maps remain in the instructions.
- WHEN syncing Claude Code, Codex, Antigravity or Copilot, THEN each host receives the same reference output-name set as that baseline, with shared output directories deduplicated through the existing group resolver.
- WHEN rendering Startup Loading maps and phase-local lists, THEN each occurrence comes from the canonical registry; ff, plan and archive retain their explicit per-phase enumeration and do not promote on-demand reads into startup loads.
- WHEN rendering conditions that status cannot decide, THEN the prose retains those conditions and the instruction to read the reference at the applicable phase.

#### REQ-TESTS-119: Reference Map Compatibility and Mutation Coverage
Tests compare registry projections, rendered phase maps and actual four-host deployment inventories against a baseline captured independently of the registry. Documentation and generated assets describe the status reference map and the skill-reference-map check with current counts.
- WHEN a phase citation is deleted, moved, changed to an unknown reference, or left present only in a startup summary, THEN applied-mutation assertions prove the phase-level guard fails; missing and orphan deployment files are covered too.
- WHEN status is exercised end to end, THEN quick, standard and backfill each have a case, with full-scale, UI-scope, host-path, empty-agent and reference-free cases covered in the remaining test matrix.
- WHEN compatibility is checked, THEN registry-derived deployment sets equal the independent four-host baseline and ordinary status routing retains its startup dependency limits.
- WHEN documenting the feature, THEN both CLI references enumerate the check, both root READMEs retain equivalent user guidance, affected Knowledge is updated and machine-owned counts are regenerated; existing unit, integration, contract, e2e, lint, typecheck, coverage, counts, agent-sync, Knowledge-sync and strict-drift gates remain required.
