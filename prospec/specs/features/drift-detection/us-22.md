## US-22: A station's reference map is checked where the station reads it [P1]

As a developer maintaining a downstream Prospec project,
I want `prospec check` to compare each configured host's deployed skills against the station reference registry, per load point,
so that a citation deleted from the phase that needs it — or a deployment left un-synced — is a located finding instead of a silent gap an agent reads past.

**Acceptance Scenarios:**
- WHEN any phase's reference citation is removed, even while another phase still names the same file, THEN the check fails and names the skill, the phase and the reference
- WHEN a registered reference is missing from a deployment, a deployed reference belongs to no load point, or the prose disagrees with the registry, THEN the check fails with actionable diagnostics
- WHEN the map is intact and the deployment agrees, THEN the check passes; unreadable inputs and a project with no configured agent are reported as skipped rather than as a pass

#### REQ-LIB-079: Phase-Level Skill Reference Drift Enforcement
The repository-scoped skill-reference-map check is appended to DRIFT_CHECK_IDS with an explicit scope and is dispatched by the shared drift assessment. Its collector reads configured shipped-skill deployments and its pure evaluator compares registry expectations, actual phase-local prose citations and deployed reference membership, independently of whether a change is in flight.
- WHEN a phase citation is removed or moved, even if another phase still names the file, THEN the check fails with the skill, phase and reference location.
- WHEN prose references an unregistered or missing reference, a registered reference is not deployed, a deployed reference is not associated with any phase, or the prose map disagrees with the registry, THEN the check fails with actionable diagnostics.
- WHEN all configured shipped deployments are readable and agree, THEN the check passes; known missing deployment files fail, while unavailable inputs or no applicable configured agents are explicitly skipped rather than certified as PASS.
- WHEN custom skills or shared host output roots are present, THEN custom skill directories are outside this check and shared shipped roots are assessed once.
- WHEN files or directory membership change during assessment or before a gate writes, THEN the existing observation/recheck mechanism detects those changes for the configured skill roots as well; no new stale-report trust path is introduced.
