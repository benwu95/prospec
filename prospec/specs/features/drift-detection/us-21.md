## US-21: Constitution Language Policy drifts from the resolved language scope [P1]

As a maintainer whose project's trust zone is written in its own language — or who reworded the seeded Language Policy,
I want `prospec check` to compare the Constitution's Language Policy Description with the rule the resolved language scope (`artifact_language` + `trust_zone_language`) renders — the same comparison `prospec upgrade` uses to offer its consent-gated rewrite,
so that the entry config's "generated from this same path set" is checked rather than asserted, and a native-language trust zone is a supported configuration instead of a silent contradiction between `CLAUDE.md`/`AGENTS.md` and the Constitution.

**Acceptance Scenarios:**
- WHEN the Constitution's Language Policy Description matches the rule rendered for the resolved scope (whitespace-normalized), THEN `language-policy-drift` passes
- WHEN the Description was reworded, or a language changed in `.prospec.yaml` under an unchanged Constitution, THEN one WARN finding names both resolved zone languages and the two remedies (accept the prospec-upgrade rewrite, or align the config)
- WHEN the Constitution is unreadable, declares no Language Policy principle, or that principle carries no `**Description**:` field, THEN the check skips with the reason — never a vacuous pass
- WHEN `trust_zone_language` is unset or English, THEN every generator renders exactly the pre-axis text, so no existing project is flagged for a feature it never opted into

#### REQ-TYPES-094: `language-policy-drift` drift check id
`DRIFT_CHECK_IDS` appends `language-policy-drift` as its 21st frozen id, additive only. Its per-id comment states what the check compares (the Constitution's Language Policy `**Description**:` against the Description `languagePolicyRule` renders for the project's resolved language scope, whitespace-normalized), that every finding is WARN-class (a fail tier would red every project whose owner reworded the seeded Description on adoption day — a forced migration), and when it skips (Constitution unreadable, no Language Policy section, or a section carrying no `**Description**:` field).
- WHEN the new id is appended, THEN the preceding twenty keep their positions
- WHEN a `runChecks` dispatch for the new id is missing, THEN compilation fails through the `Record<DriftCheckId, CheckOutcome>` exhaustiveness guard
- WHEN the evaluator's behavior changes, THEN the per-id comment is updated with it

#### REQ-LIB-074: Language Policy drift collector, evaluator and the shared comparison
`lib/language-policy.ts` exports the pure `compareLanguagePolicy(constitution, expectedDescription, scope)` returning one of `missing-section` / `no-description` / `legacy-english-seed` / `stale-seed` / `diverged` / `in-sync`: it slices the Language Policy principle, extracts its `**Description**:` field (up to the next `**Rationale**:` / `**Verify**:` / `---` / heading), collapses whitespace runs on both sides, and compares; the pre-fix seed marker keeps its legacy semantics (an English-only project whose seed also said English is `legacy-english-seed`, never nagged). `collectLanguagePolicyDrift(constitutionPath, cwd, scope, expectedDescription)` in `drift-sources.ts` reads the Constitution through `readContainedFile`, never throws out of the `runChecks` argument (any exception degrades to `available:false`), and maps the verdict into a `LanguagePolicyDriftSource` (`available:false` with a reason for unreadable / `missing-section` / `no-description`); `evaluateLanguagePolicyDrift` in `drift-checker.ts` emits one `warn` finding for `diverged` or `stale-seed`, anchored at the Constitution path, whose detail names both resolved zone languages and the two remedies (accept the `prospec-upgrade` rewrite, or align `artifact_language` / `trust_zone_language`).
- WHEN the Constitution is unreadable, has no Language Policy section, or its section carries no `**Description**:` field, THEN the source is unavailable with a reason naming which, and the check skips
- WHEN the Description matches the rendered one after whitespace normalization, THEN the verdict is `in-sync` and no finding is emitted
- WHEN the Description differs, or the old seed marker is present in a project that is not English-only, THEN exactly one WARN finding is emitted for the Constitution path
- WHEN the old seed marker is present in an English-only project whose seed also said English, THEN the verdict is `legacy-english-seed` and no finding is emitted
- WHEN `prospec upgrade` and `prospec check` judge the same Constitution, THEN both call this one comparison — no second implementation of the Description extraction or normalization exists

- WHEN `prospec check` runs, THEN the report's `checks[]` carries a `language-policy-drift` entry at the registry position
- WHEN `.prospec.yaml` changes `artifact_language` or `trust_zone_language`, THEN the expected Description changes with it and an unchanged Constitution is reported as diverged
