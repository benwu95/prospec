## US-23: Module paths git cannot read as written are refused with a rewrite hint [P1]

As a developer, or an agent, writing `module-map.yaml`,
I want every module path or generated-artifact pattern that git cannot read as written to be named with a rewrite hint,
so that I can correct the map instead of receiving a digest that never changes or covers the wrong files.

**Acceptance Scenarios:**
- WHEN a module path holds a brace (`src/{a,b}/**`), a glob holds a `..` segment or is absolute, a path begins with `:`, or a path resolves outside the project, THEN `prospec check` reports one WARN finding naming the module, the path as written and how to rewrite it, and the path contributes no file to the digest or `last_src_commit`
- WHEN a module has no supported path left, THEN it has no computable digest and a null `last_src_commit`, and its reason names the refused paths it read and points to the `unsupported-module-path` check
- WHEN a module holds a refused path, THEN neither `prospec knowledge verify` nor `prospec check` rewrites how any path in `module-map.yaml` is written
- WHEN `.prospec.yaml` resolves outside the project or cannot be read, THEN the check is skipped with its reason rather than passing with the generated-artifact patterns unread

#### REQ-LIB-107: Unsupported module path spellings are reported, never interpreted
The repository-scoped, WARN-only `unsupported-module-path` check is appended to `DRIFT_CHECK_IDS`, the preceding ids keeping their order. Its collector reads `module-map.yaml` as written, before REQ-LIB-014's clamp, together with `knowledge.generated_artifacts`, and classifies each path with the one rule REQ-LIB-015 reads paths by. A path, literal or glob, that resolves outside the project (a module path REQ-LIB-014 therefore clamps), a path that begins with `:`, and a glob that holds `{` or `}`, holds a `..` segment or is absolute are refused; a refused path contributes no file to the source digest or `last_src_commit` (REQ-LIB-015, REQ-LIB-039), and neither this check nor `prospec knowledge verify` rewrites how any path is written.
- WHEN a module path or a generated-artifact pattern is refused, THEN the check reports one WARN finding for it, naming the module or `knowledge.generated_artifacts`, the path as written, why it is refused and how to rewrite it
- WHEN a glob is written `./x/**` or `x//**`, or a literal path holds `..` or `//` and still resolves inside the project, THEN it is accepted
- WHEN every declared path and pattern is accepted, THEN the check passes
- WHEN `module-map.yaml` is absent, THEN the check is skipped with its reason
- WHEN `.prospec.yaml` resolves outside the project — a symlinked config is unsupported — or cannot be read, THEN the check is skipped with its reason rather than passing with the generated-artifact patterns unread
