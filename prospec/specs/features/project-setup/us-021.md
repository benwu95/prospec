### US-021: Managed `.gitignore` Block for Local Artifacts and prospec Skills [P0]

As a developer adopting prospec in an existing git project,
I want `prospec init` and `prospec agent sync` to keep a `.gitignore` block that ignores prospec's local artifacts and re-includes the prospec skills, and to name any rule that still ignores a skill together with lines I can add,
so that local work stays out of commits, teammates get the prospec skills on clone, and I know at once when my own rules defeat that.

**Acceptance Scenarios:**
- WHEN `prospec init` runs in a git project THEN `git check-ignore` reports the files under `.prospec/` and `prospec-report.json` as ignored
- WHEN the project has no `.gitignore` THEN init creates one containing only the prospec managed block
- WHEN the project already has a `.gitignore` THEN the content outside the managed block keeps its order (a missing final newline gets one newline before the block)
- WHEN project rules exclude skill files by file-name pattern (e.g. `*.md`) THEN after sync the prospec skill files are not ignored
- WHEN project or personal rules exclude the agent directory or its skills directory so that skill files stay ignored THEN the command succeeds and warns naming the excluding file, line and rule; when the rule is in the project directory's `.gitignore`, it also lists lines to add at the end of `.gitignore`, which it never writes
- WHEN no rule affects the agent directory THEN after sync every non-prospec file in it keeps its ignore status
- WHEN sync runs twice in a row THEN `.gitignore` does not change
- WHEN `.gitignore` cannot be read, is a symbolic link, is not valid UTF-8 or has malformed managed-block markers THEN the command succeeds, leaves `.gitignore` unchanged and prints the reason
- WHEN `.gitignore` did not exist THEN init prints a line stating it created `.gitignore`
- WHEN `.gitignore` existed THEN init prints a line stating it updated `.gitignore` with local-artifact ignores and prospec skill re-includes
- WHEN agent sync leaves the managed block unchanged THEN its output lists no `.gitignore` status line

#### REQ-LIB-106: `.gitignore` managed block ignores local artifacts and re-includes prospec skills
`syncGitignoreBlock({ cwd, skillPaths, skillNames, skillFiles })` maintains one block in `<cwd>/.gitignore` that starts at a `# prospec:auto-start` line and ends at a `# prospec:auto-end` line, reports `created`, `updated`, `unchanged` or `skipped` with warnings and suggested lines, and resolves rather than throws; `skillNames` are the shipped `prospec-*` skill directory names and `skillFiles` the skill files relative to their `prospec-*` directory. The block's content is determined by the inputs alone: it ignores `/.prospec/*` and `/prospec-report.json`, and for each distinct skill path it re-includes `/<skillPath>/prospec-*/`, each subdirectory that holds `skillFiles`, and, in each directory that holds `skillFiles`, the files whose extension is the extension of a `skillFiles` entry; every block pattern is anchored with a leading `/`. Block lines are joined with CRLF when every line break in the file is CRLF, otherwise with LF. The write step skips — writes nothing, reports `skipped` and warns with the reason — when an existing `.gitignore` is a symbolic link, is not a regular file, cannot be read, is not valid UTF-8, has either marker more than once, has only one of the two, has the end marker before the start marker, changed between the read and the write, or cannot be written; a marker line matches with or without a trailing carriage return. The bullets on creating, appending, replacing and leaving the file unchanged describe a write step that does not skip. When git reports `cwd` inside a work tree, whatever the write step reported, the writer checks the existing skill files — each skill path's `skillNames` × `skillFiles` paths that exist and have no symbolic-link ancestor below `<cwd>` — and the directories on their paths against the repository's effective ignore rules.
- WHEN `.gitignore` is absent, THEN the writer creates it containing only the block and reports `created`
- WHEN `.gitignore` has no marker line and differs from the computed file, THEN the block is appended after its content, preceded by a newline when the content is non-empty and lacks a final newline, and the writer reports `updated`
- WHEN `.gitignore` has one block that differs from the computed block, THEN only the lines between the markers change, the content before and after the block keeps its bytes and order, and the writer reports `updated`
- WHEN the computed file equals the current file, THEN the writer reports `unchanged` and writes nothing
- WHEN two runs receive the same inputs and find the same content outside the block, THEN they compute the same block
- WHEN a path lies outside every `<skillPath>/prospec-*` directory, outside `/.prospec/` and is not `/prospec-report.json`, THEN no block pattern matches it
- WHEN the check finds existing skill files excluded, THEN the result carries one warning per excluding rule, naming the rule's source (relative to `cwd`, unless git reports an absolute path), line and pattern, one skill file it excludes and how many other skill files it excludes
- WHEN rules in `<cwd>/.gitignore` exclude skill files under a skill path — a rule's source judged by comparing git's source path, which is relative to the work tree's top level, with `cwd`'s prefix in the work tree — THEN the suggested lines for that skill path list, for the directories that those rules' records hold on the paths of those skill files, from the outermost down, a re-include line immediately followed by a re-exclude-contents line with `prospec-*` in place of the skill name, and then the block's re-include lines for that skill path — its `prospec-*` directory, subdirectory and file lines, which restore what a `prospec-*` re-exclude covers in skill directories the rules left alone; when those records hold no such directory, the block's lines for that skill path alone; a rule from any other source adds no suggested line; the writer never writes suggested lines to `.gitignore`
- WHEN a skill file has a symbolic-link ancestor below `<cwd>` inside a work tree, THEN the result warns that git does not follow that link, naming it
- WHEN git reports that no repository contains `cwd`, THEN the check is skipped
- WHEN git cannot run, or the check fails or times out, THEN the result keeps the status the write step reported and warns with the failure
- WHEN the writer returns, THEN no project file other than `<cwd>/.gitignore` is left changed

#### REQ-SERVICES-130: init and agent sync maintain the `.gitignore` block
`init.execute` runs the REQ-LIB-106 writer after writing its artifacts and before writing `.prospec.yaml`, for the selected agents' skill paths and the skill names and files the shipped skill registry defines, and returns its result as `gitignore`. `agent-sync.execute` without `--cli` runs the writer after writing skills, for the skill paths of every agent configured in `.prospec.yaml` and the skill names and the skill and reference files it wrote in that run, and returns its result as `gitignore`. `quickstart.execute` returns one `gitignore` result: `created` when init created the file, otherwise `updated` when either run updated it, otherwise the agent-sync status, with the warnings of both runs, each once, and the suggested lines of the agent-sync run when it has any, otherwise those of the init run.
- WHEN `prospec agent sync --cli <agent>` runs, THEN `.gitignore` is not read or written and the result carries no `gitignore` entry
- WHEN `prospec upgrade` runs, THEN its agent-sync result carries the `gitignore` entry

#### REQ-CLI-063: Commands report `.gitignore` changes
One formatter helper renders the REQ-LIB-106 result for `init`, `agent sync`, `quickstart` and `upgrade`. `created` prints a line naming `.gitignore` as created and `updated` a line naming it as updated; both state that the block ignores prospec's local artifacts and re-includes prospec skills. `unchanged` and `skipped` print no status line. Each warning is written to stderr; when the result carries suggested lines, a line saying to add them at the end of `.gitignore` is written to stderr, followed by each suggested line on its own line.
- WHEN init creates `.gitignore` without `--quiet`, THEN its output contains the created line
- WHEN init, agent sync or upgrade changes an existing `.gitignore` without `--quiet`, THEN its output contains the updated line, and quickstart prints the line for its merged result
- WHEN the result carries warnings or suggested lines, THEN they are written to stderr, in quiet mode too
- WHEN `--quiet` is set, THEN no status line is printed
