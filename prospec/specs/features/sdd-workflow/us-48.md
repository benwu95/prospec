## US-48: Establish a Sourced Premise Before Planning [P0]

As a developer planning a change with Prospec,
I want to record the problem's original source, evidence, withdrawal conditions and verification conclusion,
so that unfinished premises return to exploration before planning consumes implementation effort.

**Acceptance Scenarios:**
- WHEN a new-contract standard/full proposal lacks required evidence or a completed conclusion, THEN validation reports the gaps and status returns to explore without regressing the change's status.
- WHEN an AI-proposed premise gains complete evidence and verification, THEN it becomes ready while retaining its original source; changing the source alone cannot repair missing fields.
- WHEN an applicable premise is blocked, THEN advancing writers refuse before writing outputs or metadata, including direct command entry and post-story scale promotion.
- WHEN new-story or ff describes a confirmed Why, THEN it uses traceable input or actual investigation results; inferred scope and defaults remain disclosed assumptions.
- WHEN explore examines an existing change, THEN it returns findings for new-story to update the same proposal and revalidate, preserving unrelated content and the acceptance amendment contract.
- WHEN no change exists, THEN new-story or ff can consume the exploration findings to create its premise.
- WHEN an existing change lacks the new version declaration, THEN it remains admissible with an explicit legacy limitation; quick and backfill keep their established workflows.
- WHEN a reproducible bug supplies the evidence, THEN an extended interview is optional but reproduction steps, expected and actual results and verification remain required.
- WHEN story or auto-draft scaffolds a new change, THEN it declares the new contract with pending unconfirmed fields rather than inventing completion.
- WHEN any premise assessment is reported, THEN it discloses that structural readiness does not authenticate sources, prove evidence or execute reproduction steps.

**Independent Test:**
Run validator, status and lifecycle writers against pending, ready, AI-source, reproduction, legacy and exempt fixtures. Assert matching assessments, byte-identical files on refusal and restored routing after completing the same proposal. Render the skills and verify section-scoped authoring and handoff contracts.

### Behavior Specifications

#### REQ-TYPES-111: Premise contracts and compatible metadata declaration
The types layer defines version 1 of the sourced-premise contract, its document schema and the ready/blocked/legacy/exempt assessment vocabulary. Metadata reads admit an absent premise_version for legacy changes; new story scaffolds declare premise_version: 1.
- WHEN a new declaration is present but unsupported or malformed, THEN it is refused rather than treated as legacy.
- WHEN a premise is declared verified, THEN its required fields are nonempty: problem, source, source_ref, evidence.kind/ref/result, withdrawal and verification.status/by/conclusion; source is user-observation, third-party-report or ai-proposed, independently of evidence kind observation or reproduction.
- WHEN evidence.kind is reproduction, THEN steps, expected and actual are additionally required.
- WHEN a document is pending, THEN it remains blocked regardless of its source; complete declarations are structural claims, not proof that evidence is true.

#### REQ-LIB-099: Shared sourced-premise assessment
A shared premise engine parses the unique unfenced proposal Premise section and evaluates the contract without performing tracker requests or executing evidence. A contained-read adapter supplies the same assessment to query and mutation consumers.
- WHEN a versioned standard/full change is assessed, THEN a unique Premise section containing one YAML mapping is required; missing/duplicate sections or keys, malformed or unclosed fences, unknown keys, blank or explicit placeholder required values and pending verification block readiness.
- WHEN Markdown contains fenced examples or CRLF line endings, THEN examples do not satisfy the live section and CRLF is accepted.
- WHEN a valid completed premise retains ai-proposed source, THEN it can be ready; changing only source cannot repair other missing evidence or verification fields.
- WHEN scale is quick or backfill, THEN the assessment is exempt; when the version declaration is absent, THEN it is legacy with an explicit limitation, never a claim of verified evidence.
- WHEN required input cannot be read, THEN the assessment names the unavailable input and does not reinterpret it as legacy.
- WHEN an assessment is returned, THEN its result, missing fields, remediation and structural-only limitation are available to consumers.

---


#### REQ-SERVICES-127: Premise admission before lifecycle writes
Planning and lifecycle mutation services consume the shared premise assessment before their first output write. They preserve existing acceptance, scale, test, review and sign-off gates.
- WHEN a new-contract standard/full premise is blocked, THEN change plan (including force), change tasks, forward change status, verify record and archive refuse before writing planning products, lifecycle metadata or archive outputs, with the explore/new-story repair path.
- WHEN a post-story scale transition would activate the gate, THEN it assesses the target scale and refuses while blocked; a story-scale change remains available so its premise can be authored.
- WHEN an async operation separates admission from the first write, THEN changed proposal or metadata inputs are refused before that write rather than accepting a stale verdict.
- WHEN legacy changes are advanced, THEN they remain admissible with the limitation disclosed; quick and backfill retain their existing workflows.
- WHEN story or auto-draft creates a change, THEN it declares the new contract and leaves unconfirmed premise fields pending; reported drift facts do not invent value, withdrawal conditions or verification conclusions.

#### REQ-TEMPLATES-245: Sourced premise authoring and exploration handoff
The proposal reference owns the sourced-premise format and language assignments: fixed English field names/enums and narrative values in the configured artifact language. Story, fast-forward and explore share its authoring boundary.
- WHEN new-story or ff authors a confirmed Why, THEN it uses traceable input or actual investigation results, and asks about missing critical evidence or routes to explore instead of inventing confirmation.
- WHEN premise-check runs, THEN explore considers impact of inaction, evidence and withdrawal conditions, returning content suitable for Premise without creating or modifying change files.
- WHEN exploration concerns an existing change, THEN new-story updates that proposal in place, preserves unrelated content and applies the existing acceptance amendment contract if scenarios change, then validates and consults status.
- WHEN no change exists, THEN new-story or ff can consume the same exploration handoff to create one.
- WHEN the original source is AI and later evidence supports completion, THEN authoring preserves the original source and records the evidence and verification conclusion.
- WHEN the reference describes quick, backfill or reproducible bugs, THEN it states their applicable contracts; reproduction can avoid an extended interview but cannot omit its required evidence structure.
- WHEN assumptions are inferred, THEN Stated Assumptions discloses them without replacing the Premise evidence.

#### REQ-TESTS-131: Sourced premise regression matrix
Regression coverage exercises premise structure, applicability, routing and write admission through unit, contract, integration and CLI tests.
- WHEN the matrix runs, THEN it distinguishes legacy from new-contract missing content, quick/backfill exemptions, AI-source completion, reproduction evidence gaps, malformed/duplicate/fenced documents and scale promotion.
- WHEN a blocked mutation is exercised, THEN outputs and metadata remain byte-identical; completing the same proposal restores the normal route without changing the source or recreating the change.
- WHEN templates are rendered, THEN section-scoped contracts pin premise authoring, return handoff, schema ownership, legacy disclosure and downstream/host neutrality.
- WHEN a new scaffold participates in an existing workflow test, THEN the test either supplies a completed premise or explicitly asserts the pending refusal; legacy fixtures remain legacy.
