## US-39: Judgment Grading Routes to the Strongest Available Tier [P2]

As a downstream project adopting Prospec's skill templates on any harness,
I want the judgment-station routing guidance to name no specific model or harness,
so that the templates route to "the strongest available tier" abstractly and never hard-code a vendor.

**Acceptance Scenarios:**
- WHEN a judgment-station skill template renders, THEN it advises routing the judgment to the harness's strongest available model / agent tier, expressed abstractly
- WHEN a judgment station records a grading context (review, verify), THEN the template also instructs honest `graded_by: in-session` self-declaration when the same session both implements and grades; a station with no recording sink (plan verifier, candidate evaluation) instructs a prose disclosure of the shared context instead
- WHEN the contract test scans the shipped judgment-station templates, THEN it asserts none contains a named model or harness string

**Independent Test:**
Render `prospec-review`, `prospec-verify`, `prospec-plan` and `references/candidate-evaluation`; assert each carries the strongest-available-tier routing wording and none matches a forbidden model/harness name list.

### Behavior Specifications


#### REQ-TEMPLATES-199: Judgment-station model-tier routing guidance (model/harness-agnostic)
The judgment-station skill templates SHOULD route their judgment to the harness's strongest available model / agent tier, expressed abstractly. `prospec-review`, `prospec-verify`, `prospec-plan` (its verifier section) and `references/candidate-evaluation` each state this routing guidance. The stations that record a grading context — `prospec-review` (the review baseline's `--graded-by`) and `prospec-verify` (each judgment dimension's `graded_by`) — additionally instruct honest self-declaration of `graded_by: in-session` whenever the same session both implements and grades; `prospec-plan`'s verifier section and `references/candidate-evaluation` have no grading-context recording sink, so they instruct a prose disclosure of the shared context instead.
- WHEN a judgment-station template is rendered, THEN it advises routing to the strongest available model / agent tier and names no specific model or harness
- WHEN the same session both implements and grades at a station that records a grading context (review, verify), THEN the template instructs recording `graded_by: in-session` honestly; a judgment station with no recording sink (plan verifier, candidate evaluation) instructs a prose disclosure of the shared context instead
- WHEN the contract test scans the judgment-station templates, THEN it asserts none contains a named model or harness string
