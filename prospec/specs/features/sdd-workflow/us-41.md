## US-41: Shipped Skill Prose Is Single-Source and Lean [P1]

As an AI executor reading a shipped skill on any project (including a weak-model tier),
I want each rule stated once where weak models read it (a NEVER list or a Gate checklist), CLI-enforced behavior delegated to a single command reference, and the knowledge-budget partial absent from the stations that write no README,
so that instruction dilution drops and the skills shrink toward their token budget without deleting load-bearing text.

**Acceptance Scenarios:**
- WHEN a shipped skill would restate a behavior the CLI computes, refuses, or prints, THEN it states it once as a single-line reference to the owning command, and the removed restatement's CLI behavior keeps service-level test coverage
- WHEN `prospec-verify` / `prospec-plan` / `prospec-implement` render, THEN they embed no knowledge-budget loading partial or Progressive-Knowledge-Loading budget table, while `prospec-knowledge-generate` and `prospec-knowledge-update` still do
- WHEN a shipped template regresses the single-source or partial-removal contract, or a preserved load-bearing anchor is dropped, THEN a `skill-format` contract test fails

**Independent Test:**
Render every shipped skill; assert `prospec-verify`/`prospec-plan`/`prospec-implement` carry no Progressive-Knowledge-Loading budget table while the two knowledge stations do, `KNOWLEDGE_LOADING_SKILLS` lists only those two, and the passive-voice keeper anchor mutation-reddens when removed.

### Behavior Specifications

#### REQ-TEMPLATES-214: Shipped skill templates carry each rule once and delegate CLI-enforced behavior
Shipped skill templates state each rule once and delegate CLI-enforced behavior to a single reference rather than restating it.
- WHEN a shipped skill would restate a behavior the CLI computes, refuses, or prints, THEN it states it once as a single-line reference to the owning `prospec` command, and the removed restatement's CLI behavior retains service-level test coverage
- WHEN a rule recurs within one skill, THEN exactly one occurrence remains — placed in the NEVER list or a Gate checklist — unless the contract test pins the rule in more than one location
- WHEN `prospec-verify`, `prospec-plan`, or `prospec-implement` renders, THEN it embeds no knowledge-budget loading partial and no Progressive-Knowledge-Loading budget table; `prospec-knowledge-generate` and `prospec-knowledge-update` still embed it
- WHEN a shipped template regresses any of the above, THEN a `skill-format` contract test fails

#### REQ-TESTS-102: Contract guards for skill-prose single-source and the narrowed knowledge-loading set
`skill-format.test.ts` pins the shipped-skill single-source contract and the narrowed knowledge-loading render set.
- WHEN the knowledge-budget rendering set is asserted, THEN `KNOWLEDGE_LOADING_SKILLS` contains only `prospec-knowledge-generate` and `prospec-knowledge-update`, and the budget-sentinel exemplar renders one of them
- WHEN `prospec-verify`, `prospec-plan`, or `prospec-implement` is rendered, THEN a negative guard asserts it carries no injected budget sentinel and no Progressive-Knowledge-Loading budget table
- WHEN a load-bearing anchor this change preserves but existing tests did not pin (the passive-voice STOP-and-ask rule) is removed, THEN a section-scoped, mutation-verified assertion turns red
