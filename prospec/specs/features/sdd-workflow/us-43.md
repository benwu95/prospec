### US-43: Agent-facing command help and escaping disclosure [P1]

As an AI agent invoking Prospec commands directly,
I want each command to explain its purpose, provide a runnable example, and describe its output and serialization,
so that I can call it correctly and interpret persisted text without relying on a skill to repeat the CLI documentation.

**Acceptance Scenarios:**
- WHEN reading help for the six agent-facing commands, THEN each provides When to use, Example, and Returns sections from the shared registry
- WHEN a table writer changes a cell through escaping, THEN its success digest reports the actual changed-cell count and escaping rule
- WHEN a command writes YAML data, THEN its help describes YAML serialization rather than Markdown-table escaping

#### REQ-TYPES-098: Typed CLI help registry with escaping disclosure
`src/types/cli-help.ts` is the single source of the enriched help text for the six commands agents call directly. It exports `HELP_ENRICHED_COMMANDS` (as const: `status`, `change log`, `review merge`, `verify record`, `learn upsert`, `spec show`), `HELP_SECTION_LABELS` (`When to use:` / `Example:` / `Returns:`), `CommandHelpSpec` (`whenToUse`, `example`, `returns`, optional `escaping: EscapingDisclosure`), `EscapingDisclosure` (`{ kind: 'markdown-table' | 'yaml-scalar'; text: string }`), `ESCAPING_RULE_TEXT` (the one sentence stating the Markdown-table escaping rule, reused by the table writers' success notice), `COMMAND_HELP_SPECS: Record<HelpEnrichedCommand, CommandHelpSpec>`, and the pure `renderCommandHelp(spec)`. The registry lives in `types` for the same reason `SKILL_DEFINITIONS` does — human-readable text every layer may read — so a later station report can quote the same help a command prints.
- WHEN a command is added to `HELP_ENRICHED_COMMANDS` without a `COMMAND_HELP_SPECS` entry, THEN `pnpm typecheck` fails
- WHEN `renderCommandHelp(spec)` runs, THEN the output carries the three section labels in order and `spec.example` verbatim
- WHEN `spec.escaping` is present, THEN its `text` is appended to the `Returns:` section; `kind` names the engine that owns the escaping (a Markdown table cell writer or the YAML scalar serializer), so a command cannot be documented with an escaping rule it does not perform

#### REQ-CLI-054: Six agent-facing commands mount registry-driven help
Each of the six commands in `HELP_ENRICHED_COMMANDS` mounts `renderCommandHelp(COMMAND_HELP_SPECS[<command>])` through Commander `addHelpText('after', …)` at registration, so `--help` prints when to use the command (and what it is not for), one complete runnable example, and what it returns.
- WHEN `prospec status --help` runs, THEN `When to use:` states it is the first command of a session and `Returns:` states it prints an `action:` line per in-flight change
- WHEN `prospec change log --help` runs, THEN `Returns:` states the entry's free text is serialized as YAML data by the yaml library (quoted only when YAML requires it) and that no Markdown-table escaping applies
- WHEN `prospec review merge --help` or `prospec learn upsert --help` runs, THEN `Returns:` states that `|` inside a cell is written as `\|`, that newlines inside a cell are flattened to a space, and that identity is the finding `id` / ledger `key`, never text comparison
- WHEN `prospec verify record --help` or `prospec spec show --help` runs, THEN the three sections are present and the example is a complete command line
- WHEN any option set or command behavior is compared before and after, THEN it is unchanged — the enrichment is help text only
- WHEN `reference/cli-reference.md` and `reference/cli-reference.zh-TW.md` describe the escaping of `change log`, `review merge` and `learn upsert`, THEN their wording states the same rule the help prints (YAML data serialization for `change log`; `|` → `\|` and flattened newlines for the two table writers) instead of `automatic character escaping`

#### REQ-CLI-055: Table-writing commands disclose escaping when it happened
`src/cli/formatters/escaping-notice.ts` exports `formatEscapingNotice(escapedCells)`, whose rule sentence is `ESCAPING_RULE_TEXT` from `types/cli-help.ts` — the same constant the help prints; `review-merge-output` and `learn-output` call it after the success digest.
- WHEN the merged round or the upsert escaped no cell, THEN the command output is byte-identical to the output before this requirement existed
- WHEN at least one cell was escaped, THEN exactly one extra line names the count and the rule (`|` → `\|`, newlines flattened to a space) so the caller knows the stored text differs from what it supplied
- WHEN the notice renders, THEN it carries no finding- or lesson-supplied text, so nothing new passes the terminal sanitizer boundary

#### REQ-LIB-078: `needsTableEscape` predicate and per-round escaped-cell count
`lib/markdown-table` exports `needsTableEscape(value): boolean`, the single predicate `escapeTableCell` uses to decide whether a cell changes when rendered, and `countEscapedCells(rows)`, which applies it over rendered rows. The review-merge and lessons-ledger engines count, over the rows they wrote or updated this round only and over the cells each row actually renders to (the same cell list the table uses), how many cells the predicate rewrites, and return it as `escapedCells`; `escapeTableCell` and `renderMarkdownTable` keep their signatures and byte-identical output.
- WHEN a value contains `|` or a line break, THEN `needsTableEscape` is true and `escapeTableCell` changes it; otherwise both leave it as-is
- WHEN a round writes or updates rows whose rendered cells need escaping, THEN the engine result's `escapedCells` equals that count; carried-forward untouched rows are not counted, and a value the merge discarded (a re-reported `lens`, or a re-reported lesson description — the stored one wins) is not counted because it never renders
- WHEN a lesson upsert is `unchanged` (a retired row, or a source change already recorded), THEN `escapedCells` is 0 — nothing was written
- WHEN a value containing `|` is escaped, rendered, and read back through `findTable` + `splitTableRow`, THEN the original string is restored; a value containing a line break reads back with the break flattened to a single space — the lossy case is a stated contract, not an accident

#### REQ-TESTS-118: Help registry completeness and table escaping round-trip contracts
`tests/contract/cli-output.test.ts` drives `createProgram().parseAsync([…, '--help'])` for every `HELP_ENRICHED_COMMANDS` entry and asserts the three section labels and the registry example verbatim; a second assertion walks the program's command tree in both directions — every registry key resolves to a registered command whose `helpInformation()` carries the three labels, and every command whose help carries them is a registry key. `tests/unit/lib/markdown-table.test.ts` extends the existing inverse describe with the round-trip, the flattened-newline case and `needsTableEscape` positive/negative cases.
- WHEN a registry key names no registered command, or a registered enriched command lacks the labels, THEN the contract turns red in that direction
- WHEN `|` replacement is removed from `escapeTableCell`, THEN the round-trip assertion turns red (mutation-verified)
- WHEN a line break is escaped and read back, THEN the assertion expects a single space, not the original break
