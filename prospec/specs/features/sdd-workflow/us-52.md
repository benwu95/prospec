# SDD Workflow — Loosened Tests and Test Gates

## US-52: Loosened Tests and Test Gates Are a Review Finding [P0]

As a developer reviewing a change with `prospec-review`,
I want the test-quality lens to rate a weakened, deleted or disabled test and a relaxed test gate as critical when the change carries no basis for it,
so that a change cannot pass review by lowering the bar its tests set — a loosening that build, the test gate and verify all leave green.

**Acceptance Scenarios:**
- WHEN a change weakens or deletes an existing assertion and neither the proposal, the delta-spec nor a recorded acceptance amendment gives a basis, THEN the test-quality lens files a `critical` finding that quotes the assertion before and after the change
- WHEN a change adds a test disable or focus marker, THEN the test-quality lens files a `critical` finding
- WHEN a change to an existing test traces to a MODIFIED or REMOVED REQ or a recorded acceptance amendment, THEN the lens does not file it as a loosening
- WHEN a change narrows the test command, enables test-evidence reuse, adds a runner exclude or lint suppression, or lowers a coverage threshold without a basis, THEN the test-quality lens files a `critical` finding
- WHEN a change edits only test-gate configuration and no test file, THEN the test-quality lens still applies

#### REQ-TEMPLATES-251: The test-quality lens grades weakened tests and relaxed test gates as critical
The test-quality lens grades a change that loosens existing tests or test gates, not only the strength of the assertions it adds. Without a basis — a MODIFIED or REMOVED REQ in the change's delta-spec, a recorded acceptance amendment, or a reason stated in the proposal, each written before the review loop — each loosening shape is `critical`; a rename or move that keeps behavior, or an assertion made stricter, is not a loosening.
- WHEN a change weakens or deletes an existing assertion without a basis, THEN the test-quality lens rates it `critical` and the finding quotes the assertion before and after the change
- WHEN a change adds a test disable or focus marker (`.skip`, `.only`, `xit`, `xdescribe` or an equivalent), THEN the test-quality lens rates it `critical`
- WHEN a change relaxes a test gate — narrows `tech_stack.test_command`, enables `test_evidence.exclude_knowledge`, adds a runner exclude, adds a lint suppression or lowers a coverage threshold — without a basis, THEN the test-quality lens rates it `critical`
- WHEN the loosening has a basis, THEN the lens does not file it
- WHEN the only basis was written by a review-round fix, THEN it does not count and the loosening is still `critical`
- WHEN the lens files or excuses a loosening, THEN the reviewer names the basis it relied on by file and line; only an acceptance amendment is checked against a record (`acceptance.revisions`), while whether a delta-spec REQ or a proposal reason predates the review is the reviewer's judgment
- WHEN a loosening finding is confirmed, THEN it is never auto-fixed: it escalates to the developer with restoring the loosened test or gate as the proposed fix
- WHEN a change edits only test-gate configuration and no test file, THEN the test-quality lens still applies, because the lens registry's test-quality summary names test-gate configuration alongside changed tests

#### REQ-TESTS-138: The loosening criteria are pinned by the criteria-table baseline
The loosening criteria are pinned inside the `## Test-Quality Lens` section, as members of the version-controlled criteria-table baseline and by their severity, basis definition and applicability.
- WHEN any loosening row is removed or reworded, THEN the criteria-table baseline test fails
- WHEN a loosening row's severity is changed from `critical`, THEN a contract test fails
- WHEN the basis definition, its before-review limit, the file-and-line citation rule, the never-auto-fix escalation rule, the before/after quoting clause or the test-gate applicability clause is removed, THEN a contract test fails
- WHEN the rendered Review Lenses table's test-quality summary no longer names test-gate configuration, THEN a contract test fails
