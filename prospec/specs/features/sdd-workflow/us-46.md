### US-46: Stations Load a Constitution Slice and a Playbook Catalog Instead of Whole Files [P0]

As an agent running the new-story, plan, tasks or review station (and the plan/implement stations that consult the team playbook),
I want `prospec constitution show --station <s>` to hand me only the Constitution content my station needs — every section outside `## Principles` verbatim plus the rules that declare `stations: all`, name my station, or declare nothing — and `prospec learn playbook --modules <m,…>` to hand me a one-line catalog of every active playbook entry with the full text of the module-matched ones,
so that each station's Startup Loading stops paying for the whole Constitution and the whole playbook, while a slice is never worse than the full file: an undeclared Constitution, a missing `## Principles`, or a zero-hit station falls open to the full text with a stderr WARN, and the station→rule map lives in the Constitution's own `**Verify**:` declarations rather than in skill prose or CLI code.

**Acceptance Scenarios:**
- WHEN a rule's `**Verify**:` line declares `stations: plan, review` or `stations: all`, THEN `check --json` carries it on `structural.constitution.rules[].stations` and an unknown station name, an `all` mixed with names, or an empty list is a `constitution-severity` WARN
- WHEN `constitution show --station <s>` runs against this project's Constitution, THEN the slice contains every non-Principles section verbatim and the rules that declare `all`, name `<s>`, or declare nothing, every output line appears in the full text, and `estimateTokens(slice) < estimateTokens(full)` at story, plan, tasks and review
- WHEN the Constitution has no `## Principles`, no rule declares `stations:`, or no rule matches the station, THEN stdout is byte-identical to the file, stderr names the reason, and the exit code is 0
- WHEN `learn playbook --modules <m,…>` runs, THEN every active entry has one catalog line, module-matched entries print first with their full text, retired entries never appear, and `--id PB-NNN` prints one entry
- WHEN the four stations' Startup Loading is rendered, THEN the item count, order and `[STABLE]`/`[DYNAMIC]` annotations are unchanged, the Constitution item runs the slice command, plan item 4 runs `prospec spec show <feature> --story <ids>`, plan and implement run the catalog command, and verify, explore, ff, learn and archive are untouched

#### REQ-LIB-093: Constitution station slice engine
`lib/constitution-slice.ts` exports `sliceConstitution(markdown, { station })`, `sliceConstitutionRule(markdown, name)` and `normalizeStationName(input)`. A slice is built as a line mask over the original text: every line outside the `## Principles` section is kept, and inside it a rule block — from its `###` heading (deeper `####` headings belong to that block) to the next `###` heading, a whole-line `---` rule (judged on fence-blanked lines, so a table row or a fenced `---` never closes a block), or the section end — is kept when the rule declares `stations: all` (a list that contains `all` counts as all stations), lists the requested station, or declares no `stations:` at all (undeclared is never read as "no station"); only a rule that explicitly names other stations is dropped. Non-rule lines inside Principles (a trailing comment, the text after a `---`) are always kept. The engine consumes the parser's section and rule boundaries (REQ-LIB-032) and defines no heading rule of its own.
- WHEN at least one rule is kept, THEN the result is `kind: 'sliced'` with `matched` (name, `check_id`, `coverage`), `undeclared` (the rule names kept because they declare nothing) and `excluded` (the rule names dropped), and every output line appears verbatim in the input
- WHEN a Constitution is only partly declared (for example the seeded Language Policy alone carries `stations: all`), THEN every undeclared rule is present in every station's slice
- WHEN a rule's `stations:` clause lists no station, THEN it is read as undeclared (kept in every slice, and alone it is no declaration, so the result is `no-declarations`) and `constitution-severity` warns
- WHEN the markdown has no `## Principles` section, no rule declares `stations:`, or every rule is declared and none names the station or `all`, THEN the result is `kind: 'full'` with `reason` one of `no-principles` | `no-declarations` | `no-match` and `text` byte-identical to the input — never empty
- WHEN `normalizeStationName` receives a mixed-case name, a `prospec-` prefix, or a skill name such as `new-story`, THEN it resolves through `STATION_SKILLS` to the `SDD_STATIONS` member, and a name outside that set is refused with the valid names listed
- WHEN `sliceConstitutionRule` names a rule, THEN every rule with that exact name is returned (a duplicate name is disclosed), and a miss lists the available names
- WHEN the engine runs, THEN it performs no I/O and hard-codes no rule name or station→rule mapping

#### REQ-SERVICES-122: `constitution show` service
`services/constitution-show.service.ts` `execute({ cwd, station?, rule? })` resolves the Constitution path through `resolveBasePaths`, reads it through the contained reader with the repository root as the containment root (the same root `collectConstitutionRules` uses, so a `base_dir` escaping the repo is refused rather than read), hands the text to `lib/constitution-slice` and returns the engine result plus `tokens: { slice, full }` from `estimateTokens`. It decides nothing about relevance.
- WHEN the Constitution file cannot be read, THEN the service throws `PrerequisiteError` naming the path — there is no full text to fall back to
- WHEN `station` resolves and the engine returns `kind: 'full'`, THEN the service returns that result unchanged so the formatter can print the full bytes and the reason
- WHEN `rule` names no rule, THEN `PrerequisiteError` lists the available rule names; when neither or both selectors are given, THEN `PrerequisiteError` names the two flags
- WHEN the result is `sliced`, THEN `tokens.slice` is strictly less than `tokens.full` for this project's own Constitution at each of `story`, `plan`, `tasks`, `review`

#### REQ-CLI-058: `prospec constitution show --station <s> | --rule <name>`
`cli/commands/constitution.ts` registers `prospec constitution show` with `--station <name>` or `--rule <name>`; `cli/formatters/constitution-output.ts` writes the text to stdout exactly as returned — through `sanitizeTerminal`, the contract every formatter honours (an LF file round-trips byte-identically; CR and C0 control bytes are stripped as everywhere else), and without appending a trailing newline — and every diagnostic to stderr. Both CLI references list the command, claiming only that the slice is smaller than the full file and the token numbers measured with `estimateTokens`. The command is listed in `HELP_ENRICHED_COMMANDS` and mounts `renderCommandHelp`.
- WHEN `--station` produces a slice, THEN stdout is the slice and stderr carries one line naming how many undeclared rules were included and how to declare them, followed by `tokens: slice <n> / full <m> (estimateTokens)` (a fail-open run ends with `tokens: full <m>`), so the documented token numbers are reproducible with the command
- WHEN the engine fails open, THEN stdout is byte-identical to the Constitution file, stderr carries one `WARN` line naming the reason, and the exit code is 0
- WHEN `--rule` misses, or the station name is unknown, THEN the error lists the available values and the exit code is 1
- WHEN `prospec constitution show --help` runs, THEN the three help sections are present and the example is a complete command line
- WHEN `prospec --version` or `prospec status` runs, THEN the new command's service and formatter are not loaded (startup module guard)
- WHEN both CLI references are read, THEN each lists `prospec constitution show` with the fail-open guarantee, and no unmeasured percentage is claimed

#### REQ-TESTS-127: Slice, catalog and Startup Loading contracts
Contract tests pin, for this project's own Constitution and playbook: every line of each station slice (`story`, `plan`, `tasks`, `review`) appears in the full text; `estimateTokens(slice) < estimateTokens(full)` at each station; the union of all declared stations' slices plus the `stations: all` rules covers every rule under `## Principles`; every `PB-NNN` heading in `_playbook.md` parses a non-null `modules` list, and every active entry is in the catalog. Unit tests carry a killing mutation for each decision: `stations:` clause order, `all` collapsing, the `---` block boundary, the retirement exclusion and the `modules: null` non-match.
- WHEN any of the pinned properties is broken by a mutation of the engine, THEN the corresponding test turns red
