# Archive Summary Format Reference

This document defines the expected format for `summary.md`, generated by the **prospec-archive** Skill when archiving completed changes.

---

## Standard Format

### 1. Change Overview

```markdown
# {change-name} — Archive Summary

- **Archived**: {YYYY-MM-DD}
- **Original Created**: {created date from metadata.yaml}
- **Quality Grade**: {S / A / B / C / D / Unverified}
- **Issue**: {issue from metadata.yaml — omit the whole line when unregistered}
- **Plan Decision**: {option} (graded_by: {human / in-session}) — omit the whole line when the change recorded no decision
```

The `Issue` line carries `metadata.yaml`'s `issue` registration (a bare reference, a URL, or another
tracker's id — see the metadata-format reference) as a **single line**: runs of whitespace collapse to
one space, so a multi-line value cannot forge a heading or a second `- **Quality Grade**:` row in this
file. It is **omitted entirely** for a change
that registered none, so the summary — and its committed `_archived-history` copy — never implies a
tracker item that does not exist.

The `Plan Decision` line is computed by `prospec archive` into the scaffold `summary.md` (a fresh human
sign-off reads `graded_by: human`; otherwise a valid `candidates/decision.json` reads `graded_by:
in-session`). Carry it over verbatim when the Phase 2 summary replaces the scaffold — never re-derive it.

### 2. User Story Summary

Extract from `proposal.md`:

```markdown
## User Story

As a [role],
I want [feature],
So that [value].
```

---

### 3. Affected Modules

Extract from `delta-spec.md`, listing all modules with changes:

```markdown
## Affected Modules

| Module | Impact | Description |
|--------|--------|-------------|
| types | High | Added archived status to ChangeStatus |
| services | High | New archive.service.ts |
```

---

### 4. Requirement Traceability

List all REQ IDs from `delta-spec.md`:

```markdown
## Requirements

| REQ ID | Status | Description |
|--------|--------|-------------|
| REQ-AUTH-010 | ADDED | Session token rotation |
| REQ-API-011 | MODIFIED | Login endpoint returns the rotated token |
```

---

### 5. Completion Summary

```markdown
## Completion

- **Tasks**: {completed}/{total} ({percentage}%)
- **Acceptance Criteria**: {met}/{total}
```

---

### 6. Review & Verify

Carry the review/verify evidence from the change bundle (`review.md`, the verify report, `metadata.yaml` `quality_log`). Record three things: the **quality grade** (S/A/B/C/D/Unverified), the **critical/major counts with a short findings excerpt** from `review.md`, and a **`quality_log` digest** (the WARN/FAIL entries). When no review round ran, `quality_log` is empty, or the change predates these artifacts, say so plainly (`Unverified`, `no review round`) — **never fabricate** a grade or counts.

```markdown
## Review & Verify

- **Review**: {rounds} round(s), {N} critical / {M} major — {short findings excerpt, or "review-clean"}
- **Verify**: Grade {S/A/B/C/D}, {dimensions PASS summary}; {test-suite result}
- **Quality Log**: {WARN/FAIL digest from metadata.yaml, or "no WARN/FAIL"}
```

A **backfilled or reconstructed** entry (evidence recovered from the committed summary + `_lessons-ledger.md` after the gitignored bundle was lost) additionally appends a `- **Source**: {where recovered}` bullet, so a reader can tell reconstructed evidence from evidence captured live at archive time. A live archive omits it.

### 7. Knowledge Update Hints (Optional)

If affected modules have AI Knowledge documentation:

```markdown
## Knowledge Update

The following module documentation may need updating:
- `prospec/ai-knowledge/modules/{module}/README.md`
```

---

## File Length Guidelines

- Keep under **80 lines**
- Focus on traceability and searchability, not detailed implementation notes

---

## Spec Archiving

Run `prospec archive finalize <name> --bundle <archiveIdentity>` in the original source before removing its worktree. It copies `summary.md` from returned `archivePath` to `prospec/specs/_archived-history/{archiveIdentity}.md`: the committed spec-history audit trail. Reuse the returned identity; never reconstruct dates. The complete bundle stays in the main worktree project’s gitignored `.prospec/archive/`; retention is not Git-object backup.

`_archived-history/` matches `ARCHIVED_EXCLUDES`, excluding frozen REQs from drift checks. The copy preserves summary formatting; finalize refreshes both summaries’ Escalation History from metadata. Retain authored prose, fenced examples and override reasons after PASS.
